# Публикация soft.infa-ion.ru

Этот документ описывает действующий сервер, проверенный 16.10.2026.

- VPS: 213.165.34.164; Caddy: контейнер `avito-crm-caddy-1`.
- Полная конфигурация: **/opt/ion-edge/Caddyfile** → /etc/caddy/Caddyfile в контейнере.
- Сайт: **/var/www/ioninf-soft** → /srv/ioninf-soft, только чтение в контейнере.
- Другие сайты используют другие каталоги/блоки. Не заменять их.
- `Caddyfile.server` в этом репозитории — только два блока software-сайта, не вся конфигурация.
- `compose.soft.yaml` описывает дополнительный read-only mount; он уже подключён. Не перезапускать контейнер и не менять другие volumes ради обновления статики.

## Выпуск

Воспроизводимый помощник: `SOFT_SSH_KEY=/absolute/path/to/authorized/key node scripts/deploy.mjs` показывает план без публикации. После проверки плана и коммита исходников добавьте `--apply`. Он сохраняет резервную копию, проверяет staging-хеши и Caddy, заменяет только software-блоки, публикует разрешённые файлы и сохраняет журнал в test-results/deployment.json. Ключ не хранится в репозитории.

1. Чистое состояние нужного коммита: `npm ci`, `npm test`, `npm run test:downloads`; перед сменой LO — полная проверка SHA-256. Просмотреть снимки.
2. `npm run build` создаёт dist/release-manifest.json. Разворачивать только перечисленные файлы и этот манифест. Без README, исходников и .git. Проверить отсутствие лишних файлов в dist.
3. Создать отдельный каталог резервной копии `/var/backups/ioninf-soft-<release>`; сохранить в него содержимое сайта и действующий полный Caddyfile. Записать release-коммит.
4. Загрузить новую сборку в отдельный staging-каталог. Сверить перечень, размеры и SHA-256 с локальными файлами.
5. Если меняется Caddy: прочитать полный действующий файл, заменить только два блока из фрагмента. Сравнить diff. Проверить кандидата командой `caddy validate` в существующем контейнере (через docker exec).
6. Сначала скопировать хешированные ресурсы. Затем атомарно заменить index.html в существующем каталоге. Не подменять сам каталог: он bind-mounted в контейнер.
7. При первой миграции удалить только старые неразрешённые публичные файлы после резервного копирования. При обычном обновлении сохранить предыдущие хешированные ресурсы для уже открытых вкладок. Сборка определяет какие новые файлы разрешены, а архив релизов — какие прежние хеши ещё нужны.
8. При изменении конфигурации записать кандидат поверх исходного файла, сохранив inode bind mount, затем `caddy reload` в работающем контейнере. Не перезапускать остальные сервисы.
9. `npm run test:production`: точное совпадение файлов, MIME, хеши, no-cache HTML, immutable хешированных ресурсов, настоящие 404, старый домен → 308. Открыть сайт в браузере и проверить отсутствие ошибок CSP.

## Откат

Сначала вернуть ресурсы из конкретной проверенной резервной копии; index.html заменить последним. Если изменялась конфигурация, вернуть сохранённый полный Caddyfile поверх действующего файла, выполнить validate и reload. Откат не должен удалять чужие каталоги, менять DNS или перезапускать другие приложения.

Никогда не использовать широкое удаление /var/www или произвольные пути из переменной. Очистка допустима лишь внутри подтверждённого каталога этого сайта, по явному списку файлов, с резервной копией.
